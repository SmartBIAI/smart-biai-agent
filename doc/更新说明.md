# 部署更新指南

本指南适用于已经运行的 Docker 工作台和 Nginx 静态体验站点。正式应用使用 `/smart-biai-agent/`，静态体验使用 `/smart-biai-agent-static/`。部署目录独立于访问路径；更新时沿用原有目录。

当前镜像版本为 `smart-biai-agent:0.1.0-docker.2`，包含随项目分发的示例视频和封面，并统一入口补斜杠跳转。静态体验中已有的生成记录自动改用新的素材地址。

## 先确认安装方式

| 安装方式 | 工作台目录示例 | 更新方式 |
| --- | --- | --- |
| 从 Git 仓库构建 | `/opt/smart-biai-agent/deploy`，含 `compose.yml`、`.env`、`data/` | 更新源码后构建镜像 |
| 离线镜像包 | `/opt/smart-biai-agent-app`，含 `compose.yml`、`.env`、`data/` | 导入新镜像，替换部署脚本 |
| 静态体验 | `/opt/smart-biai-agent-demo`，含 `index.html` | 替换构建产物全部内容 |

先确认实际目录再执行命令。Docker Compose V2 使用 `docker compose`；若安装的是独立命令，改用 `docker-compose`。

## 备份已有工作台

以下以离线安装目录为例。从源码部署时，将 `APP_DIR` 改成自己的 `deploy/` 目录。备份期间工作台会短暂停止，备份完成后恢复。

```sh
set -e
APP_DIR=/opt/smart-biai-agent-app
BIAI_BACKUP_DIR="/opt/smart-biai-agent-backups/$(date +%Y%m%d-%H%M%S)"
umask 077
mkdir -p "$BIAI_BACKUP_DIR"
cd "$APP_DIR"
test -f .env
test -d data
docker compose -f compose.yml config --quiet
docker compose -f compose.yml stop agent
if tar -czf "$BIAI_BACKUP_DIR/workspace.tar.gz" data .env compose.yml start.sh; then
    docker compose -f compose.yml up -d
else
    docker compose -f compose.yml up -d
    exit 1
fi
```

整个 `data/` 中包含数据库、附件和加密密钥，应一起备份。更新时保留现有 `.env` 和 `data/`。自定义挂载的附件目录需要另外备份。

## 从源码更新

在项目根目录更新源码并构建正式应用镜像。原有配置和数据保留在 `deploy/` 中。

```sh
cd /opt/smart-biai-agent
git pull --ff-only
docker build -t smart-biai-agent:0.1.0-docker.2 .
cd deploy
sh start.sh
curl -fsS http://127.0.0.1:4178/healthz
docker compose -f compose.yml ps
```

若还运行静态体验，可在有 Node.js 22.13 或更新版本的环境执行 `npm ci` 和 `npm run build:demo`，将 `dist/demo/` 全部内容复制到原静态目录。服务器无需为此安装 Node.js，也可以按下节使用 Docker 构建静态页面。

```sh
cd /opt/smart-biai-agent
docker run --rm --user "$(id -u):$(id -g)" \
    --mount "type=bind,src=$(pwd),dst=/work" -w /work \
    node:22-bookworm-slim node build-demo.mjs
```

## 使用离线更新包

更新包解压后包含 `app/`（镜像与部署文件）和 `demo/`（静态页面及素材）。把更新包放到 `/opt/`，解压到独立的更新目录，随后复制需要的文件到原安装目录。

```sh
cd /opt
tar -xzf smart-biai-agent-update-0.1.0-docker.2-linux-amd64.tar.gz
UPDATE_DIR=/opt/smart-biai-agent-update-0.1.0-docker.2
cd "$UPDATE_DIR"
sha256sum -c SHA256SUMS
```

完成前面的工作台备份后，在同一终端执行：

```sh
APP_DIR=/opt/smart-biai-agent-app
docker load -i "$UPDATE_DIR/app/images.tar"
cp "$UPDATE_DIR/app/compose.yml" "$UPDATE_DIR/app/start.sh" \
   "$UPDATE_DIR/app/images.tar" "$UPDATE_DIR/app/.env.example" "$APP_DIR/"
cd "$APP_DIR"
sh start.sh
curl -fsS http://127.0.0.1:4178/healthz
docker compose -f compose.yml ps
```

`sh start.sh` 会让 Compose 使用新镜像重建容器，并继续挂载原数据目录。配置模板 `.env.example` 可以更新，实际使用的 `.env` 保持原值。若修改了域名或前缀，请在 `.env` 中核对 `BIAI_PUBLIC_ORIGIN`、`BIAI_BASE_PATH` 和 `BIAI_MEDIA_PUBLIC_ORIGIN`。

如果还需要本地保留 Nginx 示例，可复制更新包 `app/` 中的两个 `.conf.example` 文件供对照。Nginx 配置由宝塔站点管理，复制示例本身不会修改线上代理。

## 更新静态体验

确认 `DEMO_DIR` 是当前静态站点的目录。先备份，再复制新文件；`demo-assets/` 中的视频和封面需要一起上传。

```sh
DEMO_DIR=/opt/smart-biai-agent-demo
test -f "$DEMO_DIR/index.html"
test -d "$UPDATE_DIR/demo/demo-assets"
tar -czf "$BIAI_BACKUP_DIR/static-demo.tar.gz" -C "$DEMO_DIR" .
cp -R "$UPDATE_DIR/demo/." "$DEMO_DIR/"
chmod 755 "$DEMO_DIR" "$DEMO_DIR/demo-assets"
chmod 644 "$DEMO_DIR/"*.html "$DEMO_DIR/"*.js "$DEMO_DIR/"*.css
chmod 644 "$DEMO_DIR/demo-assets/"*
```

从源码构建时，把上述 `$UPDATE_DIR/demo/.` 改为项目的 `dist/demo/.`。更新完成后强制刷新浏览器。旧的对话和任务仍保存在原 URL 对应的浏览器存储中。

## 核对宝塔 Nginx 配置

进入「网站 → 自己的域名 → 配置文件」，确认 HTTPS `server` 内的补斜杠规则分别指向各自入口。已有相同 `location` 时直接修改原规则。

```nginx
location = /smart-biai-agent {
    return 301 /smart-biai-agent/$is_args$args;
}

location = /smart-biai-agent-static {
    return 301 /smart-biai-agent-static/$is_args$args;
}
```

正式应用的代理继续保留完整路径：`proxy_pass http://127.0.0.1:4178;`。静态目录继续使用原 `alias`。正式应用 `.env` 对应的设置是 `BIAI_BASE_PATH=/smart-biai-agent`。`BIAI_PUBLIC_ORIGIN` 与 `BIAI_MEDIA_PUBLIC_ORIGIN` 只填写 HTTPS 域名。

静态体验建议添加 `add_header Cache-Control "no-cache" always;`，便于更新后及时加载新脚本。完整示例见 [`baota-nginx.conf.example`](../deploy/baota-nginx.conf.example) 和 [`baota-static-nginx.conf.example`](../deploy/baota-static-nginx.conf.example)。

如配置已经正确，无需重复修改。需要修改时，保存后检查并重载：

```sh
/www/server/nginx/sbin/nginx -t
/www/server/nginx/sbin/nginx -s reload
```

## 更新后验收

用自己的域名替换以下示例中的 `agent.example.com`。

```sh
curl -I https://agent.example.com/smart-biai-agent
curl -I https://agent.example.com/smart-biai-agent-static
curl -I https://agent.example.com/smart-biai-agent/
curl -I https://agent.example.com/smart-biai-agent-static/
curl -I https://agent.example.com/smart-biai-agent-static/demo-assets/sample-video.mp4
curl -I https://agent.example.com/smart-biai-agent-static/demo-assets/sample-cover.jpg
curl -sS -D - -o /dev/null -H 'Range: bytes=0-1023' \
    https://agent.example.com/smart-biai-agent-static/demo-assets/sample-video.mp4
```

- 两个不带末尾斜杠的入口应返回 301，`Location` 分别指向各自带斜杠的地址。
- 正式入口未登录时返回 401，并提示输入工作台账号和密码。登录后可访问页面。
- 静态页面、视频和封面返回 200；视频类型为 `video/mp4`。范围读取返回 206，支持进度拖动。
- 在静态体验新建对话，查询账号、确认模拟生成、播放视频，再确认模拟发布，查看任务完成状态。
- 真实模式需要另行填写服务凭证。真实生成和发布分别在用户确认后执行。

## 回退

保留旧镜像与备份。若仅需回退应用，停止当前服务，把 `compose.yml` 中的镜像改回原标签，再用 Compose 启动。若需要恢复数据，先停止容器并另行备份当前数据，再将 `workspace.tar.gz` 解压回同一个工作台目录，恢复备份对应的配置和镜像后启动。

静态站点可从 `static-demo.tar.gz` 恢复到原目录。恢复后强制刷新浏览器，必要时清理 CDN 缓存。
