# 部署更新指南

本指南介绍自托管工作台的备份、Docker 版本更新和回退。首次安装请参阅 [Docker 部署指南](宝塔Docker首次部署.md)。当前应用版本为 v0.3.3，镜像标签为 `smart-biai-agent:0.3.3-docker.1`，功能变化见 [版本说明](../CHANGELOG.md)。

升级时沿用原部署目录、`.env` 与数据目录。应用访问路径、部署目录和数据目录分别配置，示例路径可按自己的环境修改。

## 更新前准备

确认实际工作台目录，里面应包含 `compose.yml`、`.env`、`start.sh` 和 `data/`。

| 安装方式 | 工作台目录示例 | 更新方式 |
| --- | --- | --- |
| 从 Git 仓库构建 | `/opt/smart-biai-agent/deploy` | 更新源码并构建镜像 |
| 使用导出镜像安装 | `/opt/smart-biai-agent-app` | 导入镜像并更新部署文件 |

以下命令兼容 `docker compose` 和独立的 `docker-compose`。先在同一个终端定义调用方式，再执行对应更新步骤：

```sh
if docker compose version >/dev/null 2>&1; then
    biai_compose() { docker compose "$@"; }
elif docker-compose version >/dev/null 2>&1; then
    biai_compose() { docker-compose "$@"; }
else
    echo '请先安装 Docker Compose。'
fi
```

## 备份工作台

以下以从源码部署为例。使用导出镜像安装时，将 `APP_DIR` 改成实际工作台目录。

```sh
APP_DIR=/opt/smart-biai-agent/deploy
BIAI_BACKUP_DIR="/opt/smart-biai-agent-backups/$(date +%Y%m%d-%H%M%S)"
umask 077
mkdir -p "$BIAI_BACKUP_DIR"
cd "$APP_DIR"
```

检查配置，通过后停止应用并备份，再恢复服务：

```sh
biai_compose -f "$APP_DIR/compose.yml" config --quiet
biai_compose -f "$APP_DIR/compose.yml" stop agent
if tar -czf "$BIAI_BACKUP_DIR/workspace.tar.gz" -C "$APP_DIR" data .env compose.yml start.sh; then
    biai_compose -f "$APP_DIR/compose.yml" up -d
else
    biai_compose -f "$APP_DIR/compose.yml" up -d
    echo '备份失败，请先解决备份问题。'
fi
```

确认备份成功后再更新。`data/` 包含数据库、附件和加密密钥，需要一起保留；自定义挂载的附件目录应另行备份。备份文件包含业务记录和凭证，应限制访问权限。

## 从源码更新

在项目根目录更新代码并构建镜像。随后使用原部署目录启动：

```sh
cd /opt/smart-biai-agent
git pull --ff-only
docker build -t smart-biai-agent:0.3.3-docker.1 .
sh /opt/smart-biai-agent/deploy/start.sh
```

启动脚本会识别 `docker compose` 或 `docker-compose`，检查访问配置，并通过新镜像重新创建容器。

```sh
curl -fsS http://127.0.0.1:4178/healthz
biai_compose -f /opt/smart-biai-agent/deploy/compose.yml ps
```

健康接口应返回 `{"status":"ok"}`。若修改了绑定端口，请将检查地址替换为自己的端口。

## 离线镜像更新

无法在目标服务器构建时，可在可联网且与目标服务器架构兼容的环境中，按首次部署指南构建镜像后导出：

```sh
docker save -o smart-biai-agent-images.tar smart-biai-agent:0.3.3-docker.1
```

在目标服务器准备 `/opt/biai_agent_packages/` 目录，将导出文件上传到此目录后，使用绝对路径导入：

```sh
docker load -i /opt/biai_agent_packages/smart-biai-agent-images.tar
docker image inspect smart-biai-agent:0.3.3-docker.1 --format '{{.Os}}/{{.Architecture}}'
```

将对应版本的 `deploy/compose.yml`、`deploy/start.sh` 与 `.env.example` 复制到原工作台目录，并沿用现有 `.env` 和 `data/`。例如，新版本源码位于 `/opt/smart-biai-agent`，原工作台位于 `/opt/smart-biai-agent-app`：

```sh
cp /opt/smart-biai-agent/deploy/compose.yml /opt/smart-biai-agent-app/compose.yml
cp /opt/smart-biai-agent/deploy/start.sh /opt/smart-biai-agent-app/start.sh
cp /opt/smart-biai-agent/deploy/.env.example /opt/smart-biai-agent-app/.env.example
sh /opt/smart-biai-agent-app/start.sh
curl -fsS http://127.0.0.1:4178/healthz
biai_compose -f /opt/smart-biai-agent-app/compose.yml ps
```

如果工作台目录保留有 `images.tar`，同步保存新导出文件，便于以后离线启动。配置模板 `.env.example` 可以更新，实际连接配置由 `.env` 与数据库中的已保存设置提供。

## 核对访问配置

示例使用 `https://agent.example.com/smart-biai-agent/`。检查现有 `.env`：

```dotenv
BIAI_PUBLIC_ORIGIN=https://agent.example.com
BIAI_BASE_PATH=/smart-biai-agent
BIAI_MEDIA_PUBLIC_ORIGIN=https://agent.example.com
```

Nginx 继续代理到本机端口并保留完整请求路径：`proxy_pass http://127.0.0.1:4178;`。完整配置见 [`baota-nginx.conf.example`](../deploy/baota-nginx.conf.example)。修改了域名或路径时，同步调整应用和 Nginx；配置未变时沿用现有设置。

如需修改宝塔站点配置，在保存后检查并重载 Nginx：

```sh
/www/server/nginx/sbin/nginx -t
/www/server/nginx/sbin/nginx -s reload
```

## 升级后检查

- 使用原工作台账号正常登录，查看侧栏版本是否为 `v0.3.3`。排查缓存或代理问题时，也可检查页面及健康接口的 `X-BIAI-Version` 响应头。
- 打开历史对话和任务，确认已有记录及连接设置仍可使用。
- 用模拟模式查询账号、生成图片和视频，预览后体验模拟发布并查看任务状态。
- 切到真实模式，查看当前应用已授权的图片、视频模型与社媒账号是否正常显示。
- 开始真实创作时，仍需先查看报价并确认生成；发布视频需另外确认账号、文案和时间。

图片和视频继续使用生成服务返回的地址，工作台保存参数、链接和任务信息。

## 回退版本

保留旧镜像和备份。仅回退程序时，可将 Compose 中的镜像改回原标签，再用 Compose 启动。需要恢复数据时，先停止容器并备份当前数据，再把 `workspace.tar.gz` 恢复到同一工作台目录，使用备份匹配的配置和镜像启动。
